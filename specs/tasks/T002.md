## Goal
Produce one independently reviewable research bundle — a preregistered
version-2 query plan (`docs/evidence/T002/query-plan.json`), the findings
record (`docs/research/T002_name_trademark_check.md`), a version-2 evidence
manifest (`docs/evidence/T002/manifest.json`), and sanitized raw artifacts
(`docs/evidence/T002/raw/**`) — that states whether the product name
"TrainCapsule" and the CLI/package identifiers named in source-of-truth are
clear of trademark, package-registry, and domain conflicts, or documents the
exact conflicts found. This is evidence for human/legal review, not a legal
opinion, and not a rename.

## Scope
- In scope: a preregistered query plan; a primary-register trademark search
  for the product name; a package-registry name-availability/collision
  search on every registry source-of-truth actually names an intent to use;
  a domain-availability search for every candidate domain named in
  source-of-truth; and a labeled written record of findings with sources and
  query dates.
- Out of scope: renaming the product, registering any domain/package/
  trademark, or making a legal determination. Also out of scope: treating a
  completed T002 record — regardless of its overall verdict — as satisfying
  source-of-truth's mandate to "Complete legal, domain, package, and
  trademark clearance before public release" while any trademark finding
  remains UNKNOWN or CONFLICT; and patching shared gate code
  (`tcfactory/research_policy.py`, `scripts/gates/**`) from any T002 stage,
  since those paths are outside every stage's writable paths regardless of
  what a review stage discovers about them.

## Verification (deterministic gates)
Run from the repository root once `T002.yaml` is promoted to `tasks/T002.yaml`:

```text
bash scripts/gates/contract_gate.sh T002
bash scripts/gates/secret_scan.sh
bash scripts/gates/fast_quality.sh
bash scripts/gates/real_integration.sh T002
bash scripts/gates/real_integration.sh T002 research-evidence
```

`real_integration.sh T002` invokes `scripts/gates/output_and_integration_gate.py`,
which parses the research record (`parse_research_record`,
`validate_verdict_consistency`) and validates the evidence manifest
(`validate_evidence_manifest`) against the research stage's declared
`allowed_domains`. `validate_evidence_manifest` dispatches on the manifest's
own declared `version` field: a `version: 2` manifest (this revision's
target format) is checked against the stricter `_validate_v2_manifest` path,
which requires the preregistered `docs/evidence/T002/query-plan.json`, a
matching `query_plan_sha256` digest, and per-entry binding to a planned
`query_id`/`finding_id`. This is not a paper requirement: a prior research
attempt on this task already produced exactly this version-2 shape (see
"Revision history" below), so the gate code and the expected evidence shape
are proven compatible, not merely asserted compatible. The private gate
suite `traincapsule-integration-t002` (declared in
`factory/proposals/T002.yaml` and `factory/task_catalog.yaml`) runs
independently outside this repository; its result is authoritative and
cannot be weakened here.

`real_integration.sh T002 research-evidence` invokes the same script's
generic `research-evidence` check (`_run_generic_research_evidence_gate`),
which is the strict path: it requires `require_version=2`, binds the
manifest's `query_plan_sha256` to the actual `query-plan.json` file, and
binds `current_candidate_sha` to `git rev-parse HEAD`. This is a fifth,
independent gate, not a duplicate of `real-integration`: `real-integration`
(the bare `T002`/`all` check) validates file presence, verdict labeling, and
manifest-hash reproducibility, but does **not** require or bind a version-2
query plan; only the `research-evidence` check does. Both this
`research-evidence` gate name and every pipeline stage's `machine_gates`
entry for it are also mechanically required by
`tests/test_catalog.py::test_active_t002_uses_research_v2_and_real_authority_sources`,
which `fast_quality.sh` runs; see "Revision history" for the proof that this
exact test was the sole blocking failure of the immediately preceding run.

## Failure / stop conditions (preserve UNKNOWN)
- Source-of-truth does not name any product name at all to check → stop the
  entire task; do not invent one.
- Source-of-truth names the product name or CLI token but does not name a
  specific package identifier or candidate domain for a given
  registry/registrar → do not invent the missing identifier; mark only the
  affected package/domain findings `UNKNOWN` with a documented reason, and
  still complete the checks source-of-truth does support (for example the
  trademark search on the named product name). As of this revision,
  source-of-truth names only the working codename "TrainCapsule" and the CLI
  token `traincapsule`; it does not name an intended package-registry
  publication target or a candidate domain, so most package/domain findings
  are expected to resolve `UNKNOWN` with that reason, not `CLEAR`.
- No allowlisted route to a primary trademark, package-registry, or
  domain-registrar source returns an authoritative, machine-parseable result
  without a credential this task is not authorized to create — whether
  because the route is unreachable, or because it is reachable but blocked
  by a CAPTCHA/bot-mitigation interstitial, an authentication wall, a
  query-insensitive/static response, or a nonexistent endpoint → mark the
  affected findings `UNKNOWN`, cite the exact per-route blocking mechanism
  observed, and do not guess. This condition explicitly covers
  "reachable but non-authoritative" routes as well as fully unreachable
  ones; a finding may **not** invoke this condition by asserting generic
  "no network access" when network access existed but no route was
  authoritative — a prior revision's adversary review flagged exactly this
  substitution as an unauthorized stretch of the condition's literal text
  (see "Revision history"). `UNKNOWN` is a valid terminal state and is never
  converted to a pass; if every finding ends up `UNKNOWN` for this reason,
  AC-13 degrades to verifying the stop condition rather than requiring an
  impossible `CLEAR` finding.
- A weakness in shared gate code (for example `tcfactory/research_policy.py`
  or `scripts/gates/**`) is discoverable only through mutation testing
  performed by a review stage against a throwaway clone, and is not present
  in the actual delivered candidate → this is a controller/gate defect
  outside every T002 stage's writable paths, not a T002 candidate defect.
  Record it as a distinct, non-blocking finding naming the specific
  out-of-scope path and recommending a separate controller-authorized task;
  do not attempt to patch the protected file from any T002 stage, and do not
  let this class of finding alone fail T002's acceptance criteria.
- Any of these conditions is itself evidence to write into the record
  (as `UNKNOWN` findings with documented limitations), not a reason to omit
  the deliverable entirely, unless no product name exists at all to check.

- **Revision 10's finding: the two structural causes of the recurring

  controller-owned routing code, not inferred from promoted-packet diffs.**
  This revision compared the queued/executed packet this session started

  `factory/recovery/task-packets/T002-r10.yaml`, the snapshot the "retry

  1. **The numeric divergence is not drift — it is `apply_risk_profile`
     (`tcfactory/risk.py:328-433`) working exactly as designed.** For every
     mutating/reviewer stage, `_apply_stage_profile` (line 222) takes
     `_role_override(profile, stage.role)` — a deep copy of

     role — and applies it via `stage.model_copy(update=override)`, which
     unconditionally overwrites `model`, `effort`, `max_turns`,
     `max_budget_usd`, and `task_budget_tokens` with the profile's values,
     regardless of what the proposal declared. The function's own
     docstring states this plainly: "The model proposes scope, paths,
     criteria, and gates. The deterministic controller owns model
     selection, effort, reviewer depth, repair ceilings, and minimum
     risk." `config/risk_profiles.yaml`'s `integration.roles.research`
     entry is exactly `max_turns: 18`, `max_budget_usd: 3.8`,
     `task_budget_tokens: 100000` — an exact match to every "drifted"

     proposal's stage-level numeric fields has ever survived promotion, or
     ever will, while `risk_tier` stays `integration`; this revision keeps
     the generous values anyway (per the global Max-subscription
     work-until-done directive: leave dollar/token ceilings unset and let
     the runtime decide), but no longer treats their promotion-time

     receive `allowed_domains`.** `apply_risk_profile`'s reviewer loop
