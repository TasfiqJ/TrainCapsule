# Commercial materiality discipline

A feature passing tests is necessary but not sufficient.

1. Read the task's `value_contract` before implementation.
2. Do not select metrics after seeing results.
3. Do not lower a threshold to rescue a weak result without a separately reviewed ADR grounded in new external evidence.
4. Reject vanity proxies: lines of code, raw test count, model praise, synthetic quotes, and unverified willingness-to-pay claims.
5. Foundational tasks must connect causally to a named sellable milestone.
6. Measured milestones must emit deterministic evidence at the declared path and satisfy every required condition.
7. A technically working but materially weak result returns `REDESIGN`.
8. External demand, payment, maintainer acceptance, and adoption cannot be fabricated. Mark them `EXTERNAL_EVIDENCE_REQUIRED`.
9. Explain who benefits, what costly pain changes, why the mechanism causes that change, and how the result supports a paid offer.
